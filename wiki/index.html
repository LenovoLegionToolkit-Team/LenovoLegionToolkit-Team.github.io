Lenovo Legion Toolkit Documentation

Technical reference and user manual for Lenovo Legion Toolkit (LLT), an open-source desktop utility for Lenovo gaming laptops that replaces Lenovo Vantage, Legion Zone, Legion Space, and Lenovo Hotkeys, and runs without background services or telemetry.

System Requirements

  • Operating System: Windows 10 (version 19041 or higher) or Windows 11 (64-bit).
  • Architecture: x64 native. ARM64 is not supported.
  • Runtime: Microsoft .NET 9.0 Desktop Runtime, installed by setup when it is missing.
  • Privileges: Administrative privileges, required for hardware registers, drivers, and WMI access.
  • Accounts: A single administrator account. Multi-user installations are not supported and accounts without administrator rights will not work correctly.

Supported Devices

LLT is built for Lenovo Legion laptops and the Legion Go, together with similar devices such as LOQ, IdeaPad Gaming, Lenovo Slim, ThinkBook, YOGA, and XiaoXin, including the Chinese R-series and Y-series variants. Generations 6 (2021) through 11 (2026) are supported, and some features also work on Generation 5 (2020).

Lenovo desktops and laptop families outside this list are out of scope. Individual features can still be missing on a supported model when its firmware does not report the required capability.

Required Drivers on Clean Windows Installs

If Windows was installed clean from official media, ensure the following drivers are installed from Lenovo Support so that hardware communication interfaces are active:

  1. Lenovo Energy Management
  2. Lenovo Vantage Gaming Feature Driver

Note: These two drivers are not required on Generation 10 and newer hardware.

Installation & Setup

Download the latest installer from GitHub Releases and run it. Setup requests administrator rights and installs to C:\Program Files\LenovoLegionToolkit by default. The bundled .NET Desktop Runtime is installed when it is missing.

Installing a newer version over an existing installation preserves settings, Custom Mode presets, Actions, Quick Actions, and macros. Configuration, logs, and plugins live in %LOCALAPPDATA%\LenovoLegionToolkit.

Recommended Configuration

Because the application does not install a Windows background service, it has to stay running to handle automated profile switching, Fn shortcuts, macros, and the on-screen display.

  • Open Settings -> App Behavior.
  • Set Autorun to start minimized to the tray at login. The delayed option is available for systems that need more time before hardware is reachable.
  • Enable Minimize on Close so the tray icon stays available when the window is closed.

Updating

Settings -> Updates controls the update channel (Stable, Beta, or Dev), the check frequency, and the update method. Release installers are signed with the project certificate, and the built-in updater validates that signature before installing.

Package Managers

If updates are managed by Scoop, WinGet, or a similar tool, start LLT with --disable-update-checker so the built-in updater does not compete with the package manager.

Handling Lenovo Software

LLT replaces Lenovo Vantage, Legion Zone, Legion Space, and Lenovo Hotkeys, and running any of them alongside LLT causes conflicts. Vantage, Legion Zone, and Legion Space write to the same Embedded Controller (EC) registers, and Lenovo Hotkeys owns the Fn shortcuts. Some LLT controls also stay unavailable while their services are running.

Uninstalling is not required. Settings -> Software Control exposes one toggle per suite, and only the suites that are installed are listed:

  • Disable Lenovo Vantage and ImController
  • Disable Lenovo Hotkeys, which hands the Fn shortcuts over to LLT.
  • Disable Legion Zone
  • Disable Legion Space

Disabling stops the related services, scheduled tasks, startup entries, and processes without removing files. Each toggle can be reverted from the same place.

Power Modes & Custom Tuning

Lenovo firmware exposes native power states that change Embedded Controller thermal profiles and fan tables:

Mode Internal state Value sent to the EC Description
Quiet Quiet = 0 1 Lower power limits with a low acoustic profile.
Balance Balance = 1 2 Dynamic performance scaling according to system load.
Performance Performance = 2 3 Maximum sustained clock speeds with an aggressive fan curve. Requires the AC adapter.
Extreme Extreme = 223 224 Higher thermal envelope on models that report support for it.
Custom Mode GodMode = 254 255 User-defined power limits, thermal ceilings, and fan tables.

The value written to the EC is the internal state plus one, applied through the SetSmartFanMode WMI call (writing 224 for Extreme). In Actions, the active power mode is exposed through the LLT_POWER_MODE environment variable with values 1 (Quiet), 2 (Balance), 3 (Performance), 223 (Extreme), and 255 (Custom).

  • Performance, Extreme, and Custom Mode are refused while the AC adapter is disconnected, because power limits are not applied correctly on battery power.
  • Custom Mode is skipped by the Fn+Q cycle unless the model exposes the Switch to Custom Mode with Fn+Q toggle in Settings -> Power.
  • Extreme and Custom Mode are only offered on models whose firmware reports support for them.

Custom Mode Configuration

On laptops that support Custom Mode, the application provides granular configuration of hardware limits. Not all of these are available on every model:

  • CPU Long Term Power Limit (PL1): Sustained CPU power limit in watts.
  • CPU Short Term Power Limit (PL2): Boost power envelope for short bursts.
  • CPU Peak Power Limit (PL4): Instantaneous electrical burst ceiling.
  • CPU Temperature Limit: Thermal throttling ceiling for the processor.
  • GPU Configurable TGP: Target Graphics Power for discrete NVIDIA GPUs.
  • GPU Dynamic Boost: Additional cross-load wattage allocated from CPU to GPU under gaming workloads.
  • GPU Temperature Limit: Thermal ceiling for the discrete GPU where the firmware exposes it.

Battery & Charging Controls

Battery parameters communicate with the battery charge controller through ACPI and driver interfaces.

Battery Charge Mode

The charge mode is a single setting with three values:

  • Normal: Charges to 100%.
  • Rapid Charge: Charges at the highest supported rate to reach a usable level quickly.
  • Conservation: Stops charging at a firmware-defined threshold to reduce degradation on constant AC power.

Because these values are mutually exclusive, enabling Rapid Charge or Conservation Mode replaces the other one.

  • 2021 and earlier models: Conservation Mode threshold is fixed at 60%.
  • 2022 and later models: Conservation Mode threshold is fixed at 80%.
Firmware Threshold Limitation

The Conservation Mode percentage is set by the laptop Embedded Controller (EC) firmware. It cannot be altered by software on standard Legion and LOQ models.

Overnight Battery Charging

When enabled, the device delays part of the charge while plugged in overnight, holding at around 80% and finishing to 100% by the time the laptop is used in the morning.

Charge Threshold

On devices whose Lenovo power management driver exposes the PWRMGRV charge threshold keys, LLT offers a separate Charge Threshold control with configurable Start and Stop percentages. The control is separate from the Battery Charge Mode setting.

Delayed Effect

A new threshold takes effect after the battery is unplugged and drops below the configured stop value.

Custom Fan Curves

Custom fan table control is available in Custom Mode on Generation 7 (2022) and newer laptops whose firmware exposes fan table registers.

  • 10-Point Fan Table: Configure fan speeds across temperature steps for CPU and GPU sensors.
  • Full Fan Speed: Overrides active curves and drives the fans to 100% until disabled.
Hardware Support Notice

Custom fan curves cannot be applied to Quiet, Balance, or Performance modes, because those profiles use firmware fan tables stored in the BIOS. Fan control is not available on Generation 6 (2021) and older models.

GPU Working Modes & Display

The GPU Working Mode control switches the hardware multiplexer and discrete GPU power state. Which options are offered depends on the capabilities reported by the firmware:

  • dGPU: Only the discrete GPU drives the internal display. Switching to and from this mode requires a restart.
  • Hybrid: Both GPUs are enabled and Windows switches between them as needed.
  • Hybrid-iGPU: Only the integrated GPU is used, which minimizes power draw and noise. It takes effect once the discrete GPU stops working.
  • Hybrid-Auto: Uses the integrated GPU on battery and both GPUs on AC power. Connecting a non-standard adapter switches the system to Hybrid-iGPU Only.
  • UMA: Unified memory mode, switched through the BIOS setting on models that expose it.
Restart Required

Mode changes can request a restart. LLT asks before restarting, and the switch is only complete after the system has rebooted.

Display Controls

  • Refresh Rate: Switch between the refresh rates the panel reports, and keep unused rates out of the Fn+R cycle with Exclude Refresh Rates.
  • Resolution: Change the internal display resolution.
  • Display Overdrive: Reduces panel response time to limit ghosting on supported panels.
  • Auto Color Management: Toggles Windows Auto Color Management where the display supports it.
  • HDR: Enables or disables HDR on supported panels.

Keyboard & RGB Lighting

The application talks to the keyboard controller directly and does not need any Lenovo suite for lighting control:

  • Spectrum Per-Key RGB: Individual key colors, effects, brightness, and hardware profiles.
  • 4-Zone RGB: Color and effect assignments across four keyboard zones.
  • 1-Level and 3-Level White Backlight: Brightness control for white backlit keyboards.
  • Chassis Lighting: Rear port illumination and lid panel logo lighting.

Keyboards that require Corsair iCUE are not supported. Run --force-disable-rgbkb, --force-disable-spectrumkb, or --force-disable-lenovolighting when another RGB application has to own the hardware.

Windows Dynamic Lighting

On supported keyboards, --enable-lamp-array exposes the keyboard to Windows 11 Dynamic Lighting through the Lamp Array API. While this is enabled, the Keyboard page is replaced by a Lamp Array page and LLT does not use its own per-key or zone controls.

Actions & Automation Triggers

The Actions page holds two kinds of pipeline. Actions run automatically when their trigger matches, and are evaluated from top to bottom whenever state changes. Quick Actions have no trigger and run manually from the tray menu, from Smart Keys, or from the CLI.

Available triggers:

  • Power: AC adapter connected or disconnected, low-wattage adapter connected.
  • Battery: Charge percentage drops below or rises above a configured value.
  • Lid & Displays: Lid opened or closed, displays turned on or off, external display connected or disconnected, HDR on or off.
  • Network: Wi-Fi connected to a named SSID or disconnected.
  • Processes: A process starts or stops, including game detection.
  • Time: A fixed time, a time range, sunrise or sunset, or a periodic interval.
  • Session: Session locked or unlocked, user active or inactive.
  • State: Power mode, GPU Working Mode, ITS Mode, or Custom Mode preset changed.
  • Lifecycle: Application startup, resume from sleep, device connected or disconnected.

Each pipeline can also run multiple steps in sequence, including delays, notifications, application launches, and hardware changes.

Game Detection

Game detection is configured in Settings -> App Behavior and offers these modes:

  • Automatic: Combines the methods below.
  • Discrete GPU: Reacts when a process starts using the discrete GPU.
  • Known Games: Reacts to games registered with Windows.
  • Game Mode: Reacts when Windows activates Game Mode for the foreground process.
  • Manual: Reacts to an explicit list of executable names.

Actions, macros, and game triggers only run while LLT is running.

Smart Keys & Fn Shortcuts

Settings -> Smart Keys lists the Fn hotkeys that LLT can intercept and lets each one run one or more Quick Actions instead of its default behavior.

  • Key Discovery: Press an Fn combination to find out whether it can be added as a Smart Key.
  • Mode: Choose how the key responds, including single press and double press.
  • Label and icon: Rename a key and change the icon used in the list.
  • Hidden keys: Right-click a key to hide it, and show hidden keys again from the same window.
Lenovo Hotkeys Must Be Disabled

While Lenovo Hotkeys is running it owns the Fn shortcuts, so Smart Keys, Key Discovery, and Exclude Refresh Rates have no effect. Disable it from Settings -> Software Control.

On-Screen Display & Sensors

The OSD is a floating overlay with live sensor readings. It is configured in Settings -> App Behavior through the On-Screen Display card, and it can also be shown or hidden from an Action.

  • Overlay style: A compact bar or a full panel.
  • Sensor items: Game metrics (FPS, 1% low, frame time), CPU (clock, utilization, temperature, power, voltage, fan), GPU (clock, utilization, temperature, VRAM utilization, VRAM temperature, power, fan), memory utilization and temperature, disk temperatures, and motherboard (PCH) temperature and fan.
  • Thresholds: Warning and critical colors for temperature, usage, and frame rate, including a minimum acceptable FPS and a maximum allowed gap between average and 1% low FPS.
  • Appearance: Background color and opacity, font size, corner radius, and separate colors for category, label, value, warning, and critical states.
  • Placement: Refresh interval, snapping threshold, position lock, and per-display positions that survive restarts.

The sensor values come from the hardware sensor backend. Enable Hardware Sensors in Settings -> App Behavior to poll detailed temperatures, frequencies, and power limits, and use the Dashboard to build your own set of sensor readouts.

Command Line Interface (llt.exe)

The CLI utility is located in the installation directory as llt.exe. It allows controlling toolkit functions from scripts, batch files, or terminal shortcuts, and it does not need to be run as Administrator.

For the CLI to function, the main application must be running, and CLI must be enabled in Settings -> Integrations. The same page can add llt.exe to the user PATH.

# List supported features and read a value llt feature --list llt feature get power-mode # List the accepted values, then set one llt feature set power-mode --list llt feature set power-mode performance # Set Fn Lock and white backlight level llt feature set fn-lock on llt feature set white-keyboard-backlight low # 4-zone RGB preset (1 to 4) llt rgb set 1 # Spectrum profile (0 to 6) and brightness (0 to 9) llt spectrum profile set 1 llt spectrum brightness set 5 # List and run a Quick Action by name llt quickAction --list llt quickAction "My Quick Action"

Commands

  • llt feature --list, llt feature get <name>, llt feature set <name> --list, llt feature set <name> <value>
  • llt quickAction --list, llt quickAction <name>
  • llt rgb get, llt rgb set <preset>, where the preset is 1 to 4.
  • llt spectrum profile get, llt spectrum profile set <profile>, where the profile is 0 to 6.
  • llt spectrum brightness get, llt spectrum brightness set <brightness>, where brightness is 0 to 9.

Short aliases are accepted: f for feature, qa for quickAction, r for rgb, g for get, s for set or spectrum depending on its position, p for profile, and b for brightness.

Feature Names

Feature names are reported by llt feature --list and only include what the current machine supports:

  • always-on-usb, battery, battery-night-charge, flip-to-start, fn-lock, hdr
  • hybrid-mode, instant-boot, microphone, one-level-white-keyboard-backlight
  • over-drive, panel-logo-backlight, ports-backlight, power-mode
  • refresh-rate, resolution, speaker, touchpad-lock, win-key, white-keyboard-backlight

CLI Arguments Reference

Advanced startup arguments can be passed to Lenovo Legion Toolkit.exe directly, toggled in Settings -> App Behavior -> Arguments, or added to %LOCALAPPDATA%\LenovoLegionToolkit\args.txt with one argument per line.

Argument Description
--trace Enables verbose logging to %LOCALAPPDATA%\LenovoLegionToolkit\log.
--debug Enables debug mode and the embedded C# Script Console. Unsupported configuration.
--minimized Starts the application minimized to the system tray.
--disable-tray-tooltip Disables the tray icon tooltip.
--skip-compat-check Skips the startup model check, useful after a motherboard replacement with unwritten serials. Unsupported configuration.
--allow-all-power-modes-on-battery Allows Performance, Extreme, and Custom Mode while running on battery. Power limits are not guaranteed to apply correctly, so this configuration is unsupported.
--force-disable-rgbkb Disables all 4-zone RGB keyboard communication.
--force-disable-spectrumkb Disables all Spectrum per-key RGB communication.
--force-disable-lenovolighting Disables panel logo, rear port, and white backlight control.
--enable-lamp-array Exposes supported keyboards to Windows 11 Dynamic Lighting through the Lamp Array API.
--experimental-gpu-working-mode Switches GPU Working Mode to the experimental Legion Zone method. Unsupported configuration.
--experimental-its-mode Uses the experimental ITS mode driver on ThinkBook devices. Unsupported configuration.
--disable-conflicting-software-warning Hides the banners that warn about conflicting Lenovo software.
--disable-update-checker Disables built-in update checks, useful when updates are managed by Scoop, WinGet, or similar.
--proxy-url= Proxy server URL used for network requests such as updates and package downloads.
--proxy-username= Proxy user name, if the proxy requires authentication.
--proxy-password= Proxy password, if the proxy requires authentication.
--proxy-allow-all-certs Relaxes certificate checks for HTTPS connections made through the proxy.

Downloads & Device Information

Lenovo Packages

The Downloads page lists driver and software packages that Lenovo marks as compatible with the current machine and downloads them directly, without a Lenovo suite:

  • Machine Type and Operating System selectors, which drive the package list.
  • Primary source, the same catalog Lenovo Vantage uses, and Secondary source, the Lenovo PC Support catalog.
  • Show updates only, to hide packages that are already at the newest version, plus sorting by name, category, or date.
  • Download folder selection and a shortcut to open it.

Device Information & Warranty

Clicking the device name in the title bar opens the Device Information window, displaying the machine type model (MTM), serial number, BIOS version, and warranty coverage status. Warranty start date, expiration date, and remaining days are queried directly from Lenovo: global models use the Lenovo PC Support API, while Chinese models and Chinese-language installations use the Lenovo China support API.

Known Hardware Caveats

  • Custom Mode BIOS minimums: G9CN 24 or higher, GKCN 46 or higher, H1CN 39 or higher, HACN 31 or higher, and HHCN 20 or higher are required for Custom Mode to work correctly.
  • GKCN54WW and lower: Some lighting features are disabled because that BIOS version can cause a blue screen.
  • Riot Vanguard: The DRM used by games such as Valorant is known to break RGB control. If RGB settings are missing, prevent Vanguard from starting with Windows or uninstall it.
  • Smart Fn Lock stutter: On some BIOS versions toggling Fn Lock causes a brief stutter. Disabling a BIOS option named like "Fool proof Fn Lock" has resolved it on affected machines.
  • GPU overclock recovery: If an unstable GPU overclock prevents booting, disable GPU overclocking in the BIOS or delete gpu_oc.json from %LOCALAPPDATA%\LenovoLegionToolkit in Safe Mode.

Organization Repositories & Role in LLT

The LenovoLegionToolkit-Team organization maintains several focused open-source repositories that provide the underlying hardware abstractions, telemetry interfaces, and extension mechanisms for the main application. The hardware wrappers are maintained forks of the upstream projects.

Repository Primary Role Integration in Lenovo Legion Toolkit
LenovoLegionToolkit Main Desktop Application Host WPF application, user interface, Embedded Controller (EC) features, automation processor, and tray coordinator.
LenovoLegionToolkit-Plugins Modular Plugin Library DLL-based plugins that add pages and behavior to the host application, starting with the advanced CustomFanCurve algorithm.
HarmonyBridge Runtime Method Patching Plugin module that gives other plugins runtime method patching through the Harmony library.
LibreHardwareMonitor Hardware Sensor Telemetry Maintained fork that provides sensor polling for CPU, GPU, memory, and PCH temperatures, power limits, and fan speeds.
NvAPIWrapper NVIDIA Hardware Control Managed wrapper for the NVIDIA API, used for GPU clock offsets, TGP targets, P-state handling, and discrete GPU power state checks.
WindowsDisplayAPI Windows CCD Display Control Managed wrapper for the Windows Connecting and Configuring Displays (CCD) APIs, used for refresh rate changes, resolution changes, and display topology queries.
PresentMonFps Frame Rate Metrics Engine Managed wrapper for Intel PresentMon, used to produce the frame rate and frame time values shown in the OSD.
ZenStates-Core AMD Platform Control Low-level register and SMU interop library used for AMD Ryzen power limits, Curve Optimizer, and Curve Shaper settings.
LenovoLegionToolkit-Team.github.io Documentation & Web Portal Hosts the public landing page and this documentation.

Plugins & Extensibility

LLT discovers plugins at startup by scanning %LOCALAPPDATA%\LenovoLegionToolkit\Plugins. An assembly counts as a plugin when it contains a public class that implements LenovoLegionToolkit.Lib.Station.Core.IExtensionProvider.

  • Single file plugin: Place <Name>.dll directly in the Plugins folder.
  • Folder plugin: Create a subfolder, for example Plugins\CustomFanCurve, and place CustomFanCurve.dll inside it.
  • Shared dependencies: Place assemblies used by more than one plugin in Plugins\Dependency.

A plugin registers navigation pages and writes to its own log file through the extension context. Plugin logs are stored as %LOCALAPPDATA%\LenovoLegionToolkit\log\plugin_<pluginId>.log.

Developing Plugins

A plugin is a .NET class library targeting net9.0-windows10.0.26100 that references LenovoLegionToolkit.Lib with Private=false and ExcludeAssets=runtime so core assemblies are not bundled. Building the plugin projects requires the LLT_SOURCE environment variable pointing at a local clone of the main repository. Guidelines and sample implementations live in the LenovoLegionToolkit-Plugins repository.

Security Alerts & Code Signing

Because Lenovo Legion Toolkit interacts directly with low-level Windows APIs, drivers, and keyboard hooks, generic antivirus scanners may occasionally produce false-positive heuristic alerts.

All official release builds:

  • Are built from open source by public GitHub Actions runners.
  • Are signed with the project Authenticode certificate, which the built-in updater validates before installing an update.
  • Publish full, verifiable source code for independent audit.

The project certificate lets the updater confirm that an installer came from the official build process. It is not issued by a commercial certificate authority, so SmartScreen and similar reputation systems may still warn on a new release.

Collecting Diagnostic Logs

When reporting issues or requesting compatibility investigation, diagnostic logs provide the hardware register and state outputs that are needed to help.

Enabling Logs via Settings (Standard Method)

  1. Open Settings -> App Behavior.
  2. Enable Enable Logging.
  3. Reproduce the issue or hardware condition.
  4. Collect the files from %LOCALAPPDATA%\LenovoLegionToolkit\log.

Startup Logging (For Startup Crashes)

  1. Ensure the application is completely closed and not in the system tray.
  2. Open the Windows Run dialog (Win + R).
  3. Execute: "C:\Program Files\LenovoLegionToolkit\Lenovo Legion Toolkit.exe" --trace
  4. The title bar should show [LOGGING ENABLED]. Reproduce the condition, close the app, and collect files from %LOCALAPPDATA%\LenovoLegionToolkit\log.

If LLT was installed to a different folder, adjust the executable path accordingly.

Attach the collected files to a new issue at GitHub Issues, together with the full model name and a short description of which features work and which do not.
